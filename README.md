# todoapp — TypeSafe タスク自動分類CLI

タスク文（自由記述）を **TypeSafe の System One モデル（Jev）** に渡し、
**カテゴリ・優先度・分割要否** を「型付きの判断＋確率」として受け取る最小CLIデモです。

生成AIのように文章を返すのではなく、**コードがそのまま使える構造化された判断**が返るのがポイント。
確信度（confidence）が低い判断は自動確定せず、**人間レビューに回す**設計になっています。

## 何をするか

1件のタスクに対し、1回の API 呼び出し（`systemOne`）で以下の3判断をまとめて取得します。

| 判断 | プリミティブ（判断の最小単位） | 返るもの |
|---|---|---|
| **カテゴリ** | `choice`（候補から1つ選ぶ） | `仕事 / 仕入れ・発注 / シフト / 販促・SNS / クレーム対応 / 設備・修繕 / 衛生・HACCP / 教育・研修 / 家庭 / その他` ＋ 各確率 |
| **優先度** | `score`（順序ルーブリック） | 0〜3の期待スコア（小数あり）＋ 確信度 |
| **期日** | （コード側で計算） | 優先度スコアから JST の具体的な期日を算出（意味判断はAI・日付計算はコード） |
| **進捗** | `choice` | `未着手 / 進行中 / 完了 / 停滞` をメモ等から抽出 ＋ 確信度 |
| **分割要否** | `noul`（yes/no） | 「分割した方がよい」の確率 |

さらに **重複検知**（`noul`）で、新しいタスクが既存タスクと意味的に同じかを判定できます（`--dedupe`）。

### 確信度による振り分け（不確実性ハンドリング）

- 確信度 `≥ 0.7` … 自動でカテゴリ・優先度を適用
- 確信度 `< 0.7` … `⚠ 要確認` を立てて **人間レビュー行き**
- 分割要否は中間帯（0.4〜0.6）なら判断保留

しきい値は `src/classify.ts` の `CONFIDENCE_THRESHOLD` で変更できます。

## 2つの使い方

- **Web版**（ブラウザ）… Vercel にデプロイして使う。APIキーはサーバー側に保持し、ブラウザには渡さない
- **CLI版**（ターミナル）… ローカルでタスク文を分類する

## セットアップ

Node.js 20 以上が必要です。

```sh
npm install
npm run build
```

## Web版（Vercel）

このリポジトリは Vercel にそのままデプロイできます。

- `public/index.html` … 静的フロント（タスク入力フォーム＋結果表示）
- `api/classify.ts` … サーバーレス関数。`TYPESAFE_API_KEY` がVercelのEnvironment Variablesに
  設定されていれば**本物のJev判定（live）**、未設定なら**デモ判定（demo）**を返す
- APIキーはサーバー側の環境変数にのみ保持し、ブラウザには一切露出しない

デプロイ後、トップページのフォームからタスク文を入力すると分類結果が表示されます。
本番判定を有効にするには、Vercelのプロジェクト設定で `TYPESAFE_API_KEY` を追加してください。

## CLI版の使い方

### 1. まず試す（demoモード・APIキー不要）

本物のAPIは呼ばず、キーワードによる**模擬判定（モック）**で動作イメージを確認できます。

```sh
npm run demo -- "明日までに業務用オリーブオイルを発注する"
npm run demo -- "インスタの新メニュー告知を投稿し、POPも差し替える" "今週の販促"
```

出力例:

```
■ タスク: インスタの新メニュー告知を投稿し、POPも差し替える
  メモ: 今週の販促
  モデル: jev-latest

● カテゴリ : 販促・SNS  (確信度 100%)
● 優先度   : 中（今週中）  [レベル 1 / スコア 1.03]  (確信度 76%)
● 分割要否 : 分割推奨  (Yes確率 95%)
...
→ 判断: 全項目が高確信度のため【自動適用OK】
```

> demoモードはあくまで動作イメージ用の模擬判定です。実際の Jev モデルの精度・確信度とは無関係です。

### 2. 本番モード（TypeSafe API を実際に呼ぶ）

APIキーを設定します（`.env.example` を参照）。

```sh
export TYPESAFE_API_KEY=sk-...
npm run classify -- "今日中に来週のスタッフシフトを確定してLINEで連絡"
```

### オプション

- `--demo` … APIキー不要のオフライン模擬判定
- `--json` … 結果をJSONで出力（他プログラムへ受け渡す用）

```sh
npm run demo -- --json "食材の在庫チェックと発注書の作成"
```

### 重複検知（`--dedupe`）

先頭を新タスク、以降を既存タスクとして、意味的な重複を判定します。

```sh
npm run demo -- --dedupe "オリーブオイルを発注する" "オリーブオイルを発注" "トマト缶を補充"
```

> 文字列類似度ではなく **意味** で判定するため、本番モード（Jev）では「油を頼む」≒「オリーブオイル発注」のような言い換えも重複として検知できます（demoモードは文字ベースの簡易判定のため言い換えには弱いです）。

## 構成

```
src/
  questions.ts     判断の定義（カテゴリ・優先度・分割・進捗・重複の質問プリミティブ）
  classify.ts      systemOne 呼び出し＋確信度による振り分けロジック（本体・共有）
  duedate.ts       優先度スコアから期日を計算（JST・純粋関数）
  dedupe.ts        noul による意味的な重複検知
  demo-client.ts   APIキー不要のデモ用モッククライアント
  cli.ts           コマンドライン入出力（分類 / --dedupe）
api/
  classify.ts      Vercel サーバーレス関数（src のロジックを共有）
public/
  index.html       Web版フロント（静的）
vercel.json        Vercel ビルド設定
```

CLI版・Web版とも `src/classify.ts` の `classifyTask()` を共有しています。

判断の中心は `src/classify.ts` の `classifyTask()`。ワークフローの主役はコード側で、
TypeSafe には「意味の理解が要る部分（分類・優先度づけ・分割判断）」だけを任せています。

## 技術メモ

- SDK: [`@typesafe-ai/sdk`](https://www.npmjs.com/package/@typesafe-ai/sdk) v0.6 系
- 既定モデル: `jev-latest`（`TYPESAFE_DEFAULT_MODEL` で上書き可）
- APIルート: `https://api.typesafe.ai`（`TYPESAFE_BASE_URL` で上書き可）
- 詳しい概念・API仕様は [TypeSafe ドキュメント](https://docs.typesafe.ai/) を参照
